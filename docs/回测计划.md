|----|------|
| 数据源 | 新浪财经API（主）/ 东方财富API（备） |

| 频率 | 日线 + 30分钟 |
| 时间范围 | 2023-01-01 ~ 2026-03-31（约3年+，覆盖牛熊转换） |
| 日线数据量 | 每只约 750 根（3年 × 250交易日） |
| 30分钟数据量 | 新浪API上限约1023根 ≈ 约128个交易日（约6个月） |

### 2.2 30分钟数据不足的解决方案

新浪API 30分钟线最多返回 ~1023 根（约6个月），不足以覆盖3年。解决思路：

**方案A：分批拉取**（推荐）
- 东方财富API支持指定 beg/end，理论上可以分段拉取历史30分钟数据
- 每次拉取3个月，合并后去重

**方案B：仅回测日线**
- 先只用日线做全周期回测，30分钟作为增强验证
- 回测结果分两层：「日线级别胜率」和「日线+30分钟级别胜率」

**方案C：本地数据缓存**
- 从今天开始每天运行数据采集，逐步积累30分钟数据
- 存储为本地CSV/Parquet，回测直接读取

**决策**：先用方案B启动（日线全周期 + 30分钟最近6个月），后续用方案A补全30分钟数据。

#### WalkForwardEngine（核心）

```python
class WalkForwardEngine:
    """滑动窗口分析引擎 — 回测的核心"""
    
    def run(self, klines: List[Kline], 
            min_lookback: int = 60,
            step: int = 1) -> List[AnalysisSnapshot]:
        """
        从min_lookback开始，每步向前推进step根K线，
        对当前窗口运行缠论分析。
        
        返回每个时间点的分析快照，包含：
        - 当前识别到的所有买卖点
        - 走势类型
        - 中枢结构
        - MACD状态
        """
        snapshots = []
        for t in range(min_lookback, len(klines), step):
            window = klines[:t+1]
            result = self._analyze_window(window)
            snapshots.append(AnalysisSnapshot(
                bar_idx=t,
                date=klines[t].date,
                price=klines[t].close,
                trend=result['trend'],
                hubs=result['hubs'],
                strokes=result['strokes'],
                buy_sell_points=result['buy_sell_points'],
                macd_state={...},
            ))
        return snapshots
```

**关键设计**：`_analyze_window` 直接调用 `chanlun_engine` 的函数链（`compute_macd → inclusion_processing → find_fractals → find_strokes → find_hubs → check_divergence → find_buy_sell_points`），但**不从文件读取**，而是直接接受 Kline 列表。

**需要重构 chanlun_engine.py**：
- 现有 `analyze_level(filepath, level_name)` 从文件读取
- 新增 `analyze_klines(klines: List[Kline], level_name: str)` 直接分析内存数据
- `analyze_level` 改为调用 `parse_klines` + `analyze_klines` 的组合

## 四、回测模式

### 4.1 模式一：单标的信号回测

**目的**：验证缠论引擎的信号准确率（假设H1、H3）

```
输入: 单只ETF的历史K线
处理: 滑动窗口 → 信号检测 → 统计信号后续走势
输出: 
  - 各类买卖点的出现次数
  - 买点后 5日/10日/20日 涨幅分布
  - 卖点后 5日/10日/20日 跌幅分布
  - 信号胜率（买点后上涨的比例）
  - 信号盈亏比
  - 日线 vs 30分钟信号的对比
  - 共振信号 vs 非共振信号的对比
```

### 4.2 模式二：单标的策略回测

**目的**：验证「信号 + 仓位管理 + 止损」组合的盈亏（假设H1、H5）

```
输入: 单只ETF + 交易规则
处理: 滑动窗口 → 信号 → 仓位调整 → P&L计算
输出:
  - 资金曲线
  - 总收益率 / 年化收益率
  - 最大回撤
  - 夏普比率
  - 胜率 / 盈亏比
  - 交易列表（进场/出场/持仓时间/盈亏）
  - 对比基准：买入持有同一ETF
```

### 4.3 模式三：轮动策略回测

**目的**：验证轮动评分选择的有效性（假设H2、H4）

```
输入: 6只ETF的历史K线 + 轮动评分算法
处理:
  每个「评估日」（如每周五收盘）:
    1. 对6只ETF分别运行缠论分析
    2. 计算五维度评分
    3. 排名选出最优指数
    4. 如果最优指数变化，模拟换仓
    5. 未变化则继续持有
输出:
  - 轮动策略资金曲线
  - 对比基准1: 等权持有6只ETF
  - 对比基准2: 持有沪深300ETF
  - 对比基准3: 每月随机选一只ETF
  - 换仓次数 / 年换手率
  - 每次换仓的盈亏
  - 分年度收益
```

### 4.4 模式四：参数敏感性分析

**目的**：验证系统对参数变化的鲁棒性

## 五、消除偷看偏差（Look-ahead Bias）

这是缠论回测最关键的技术点。

### 5.1 笔的回溯修正问题

缠论中，笔的划分可能因后续K线而**被修正**。例如：
- 第T天识别到底分型，形成一笔
- 第T+2天出现更低的底分型，之前的笔被重新划分

在回测中，我们记录的是「**信号首次出现且持续稳定存在**的时间点」，而非信号对应的K线日期。

### 5.2 信号稳定性窗口

```python
STABILITY_WINDOW = 3  # 信号必须连续存在3个时间步才算确认

# 在WalkForwardEngine中:
for t in range(min_lookback, len(klines)):
    snapshot = analyze(klines[:t+1])
    
    for bsp in snapshot.buy_sell_points:
        key = (bsp.type, bsp.date, bsp.price)
        if key not in signal_counter:
            signal_counter[key] = 0
        signal_counter[key] += 1
        
        if signal_counter[key] == STABILITY_WINDOW:
            # 信号确认！可以在 t+1 执行
            confirmed_signals.append(bsp)
    
    # 清除不再出现的信号
    current_keys = {(p.type, p.date, p.price) for p in snapshot.buy_sell_points}
    for key in list(signal_counter.keys()):
        if key not in current_keys:
            del signal_counter[key]  # 信号消失，重置计数
```

### 5.3 执行延迟

所有交易执行时间 = 信号确认时间 + 1个交易日（取次日开盘价 + 滑点）。

## 六、绩效指标

### 6.1 收益指标

| 指标 | 公式 |
|------|------|
| 总收益率 | (期末资产 - 初始资金) / 初始资金 × 100% |
| 年化收益率 | (1 + 总收益率) ^ (252 / 交易天数) - 1 |
| 超额收益 | 策略年化 - 基准年化 |

### 6.2 风险指标

| 指标 | 公式 |
|------|------|
| 最大回撤 | max(peak - trough) / peak |
| 最大回撤持续期 | 从峰值到恢复峰值的天数 |
| 波动率 | std(日收益率) × √252 |
| 下行波动率 | std(负收益率) × √252 |

### 6.3 风险调整收益

| 指标 | 公式 |
|------|------|
| 夏普比率 | (年化收益 - 无风险利率) / 波动率 |
| 索提诺比率 | (年化收益 - 无风险利率) / 下行波动率 |
| Calmar比率 | 年化收益 / 最大回撤 |

### 6.4 交易质量

| 指标 | 说明 |
|------|------|
| 胜率 | 盈利交易数 / 总交易数 |
| 盈亏比 | 平均盈利金额 / 平均亏损金额 |
| 单笔最大盈利 | |
| 单笔最大亏损 | |
| 平均持仓天数 | |
| 最长连续盈利 | |
| 最长连续亏损 | |

### 6.5 缠论专项指标

| 指标 | 说明 |
|------|------|
| 一买胜率 | 一买信号后上涨的比例 |
| 二买胜率 | 二买信号后上涨的比例 |
| 三买胜率 | 三买信号后上涨的比例 |
| 信号消失率 | 信号出现后又消失的比例（笔被重新划分） |
| 共振增强比 | 共振信号胜率 / 非共振信号胜率 |
| 背驰准确率 | 背驰识别后趋势确实反转的比例 |
| 评分预测力 | 高评分指数下月涨幅 vs 低评分指数下月涨幅 |

def analyze_klines(klines: List[Kline], level_name: str) -> dict:

## 九、性能考量

### 9.1 计算复杂度

滑动窗口回测的计算量 = 数据长度 × 每步分析成本：

| 场景 | K线数 | 步数 | 每步成本 | 总分析次数 |
|------|-------|------|---------|-----------|
| 单标的日线 | 750 | 690 | 快（笔/中枢构建） | 690 |
| 单标的30分 | 1023 | 963 | 快 | 963 |
| 6标的日线轮动 | 750×6 | 690 | 6×分析 | 4,140 |
| 6标的双级别 | (750+1023)×6 | 690 | 12×分析 | 8,280 |

单次分析耗时估计 < 50ms（纯Python，无外部I/O），总计 < 7分钟，无需优化。

### 9.2 可选优化

如果需要大量参数组合测试（Phase 5），可以：
- 增量分析：新增1根K线时只更新最后部分，而非全量重算
- 多进程：用 `multiprocessing` 并行跑不同参数组合

## 十、风险与限制

| 风险 | 影响 | 缓解 |
|------|------|------|
| 30分钟数据历史不足 | 无法回测30分钟信号的长期表现 | 先用日线，后续补数据 |
| ETF上市时间不同 | 512100(2022上市)、588000(2020上市) 历史较短 | 按各自上市日起算 |
| 复权处理 | 新浪API返回的是否为前复权数据需验证 | 拉取后与已知数据对比验证 |
| 笔划分参数单一 | 当前仅用4根间距，可能不是最优 | Phase 5 参数敏感性分析覆盖 |
| 过拟合风险 | 参数调优可能导致过拟合 | 时间序列交叉验证（训练集/验证集/测试集） |
| 缠论主观性 | 笔、中枢划分存在部分主观判断 | 引擎已机械化，保持规则一致 |

### 过拟合防控

1. **时间序列分割**：
   - 训练集：2023.01 ~ 2024.12（参数调优）
   - 验证集：2025.01 ~ 2025.06（参数选择）
   - 测试集：2025.07 ~ 2026.03（最终评估，仅跑一次）

2. **规则**：测试集结果仅用于最终报告，不能回头调参数。

## 十一、成功标准

回测完成后，用以下标准判断系统是否值得实盘使用：

| 标准 | 阈值 | 说明 |
|------|------|------|
| 缠论买点胜率 | ≥ 55% | 高于随机（50%）才有意义 |
| 轮动策略年化 | > 沪深300年化 + 3% | 需要超额收益覆盖交易成本 |
| 最大回撤 | < 20% | 风险可控 |
| 盈亏比 | ≥ 1.5 | 即使胜率不高，盈亏比补偿 |
| 夏普比率 | ≥ 0.8 | 风险调整后收益可接受 |
| 信号消失率 | < 30% | 引擎信号稳定性 |
| 共振增强比 | > 1.2 | 多级别共振确实提升效果 |

如果无法满足以上多数标准，需要重新审视：
1. 缠论引擎的笔/中枢划分规则
2. 评分权重分配
3. 仓位管理策略
4. 是否需要引入非缠论辅助指标
