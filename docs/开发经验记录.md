## LRN-20260331-001 | A股图表配色必须使用红涨绿跌

**标签**: #correction #chanlun
**优先级**: high
**状态**: validated
**分类**: correction

### 详情

在生成缠论K线图HTML时，初始使用了西方惯例配色（绿涨红跌），被用户纠正为A股惯例：
- **红色** = 上涨/买点/好/阳线/MACD红柱 → `#f85149`
- **绿色** = 下跌/卖点/差/阴线/MACD绿柱 → `#3fb950`

涉及修改的代码位置：
1. `scripts/chanlun_engine.py` — 个股独立图表模板（CSS + Canvas JS）
2. `scripts/build_standalone_html.py` — 自包含HTML生成脚本（CSS + Canvas JS）

具体修改点：
- CSS: `.bsp-badge.buy` 红色, `.bsp-badge.sell` 绿色
- CSS: `.badge-buy` 红色, `.badge-sell` 绿色
- Canvas: buy point marker `#f85149`(红), sell point marker `#3fb950`(绿)
- BSP list: buy price 红色, sell price 绿色
- Legend: 买点红色, 卖点绿色
- K线阳线已是红色、阴线已是绿色（无需修改）
- MACD红柱(正)已是红色、绿柱(负)已是绿色（无需修改）

### 改进措施

以后所有涉及A股相关的图表、HTML、可视化，一律使用红涨绿跌配色。

## LRN-20260331-002 | 移动端HTML必须自包含，不能使用iframe引用外部文件

**标签**: #correction #chanlun
**优先级**: high
**状态**: validated
**分类**: correction

### 详情

最初在移动版HTML中使用 `<iframe src="../../xxx/缠论分析图.html">` 引用各指数独立K线图。用户将HTML发送到手机后发现K线图无法显示，因为iframe引用的是相对路径的外部文件，这些文件在目标设备上不存在。

### 改进措施

生成可独立发送的HTML报告时，必须使用**自包含方式**：
1. 将所有K线数据（dailyData, min30Data × 6个指数）直接内嵌到JavaScript中
2. 将Canvas渲染引擎代码内嵌
3. 不使用任何外部文件引用（iframe src, script src, link href 等）
4. 单文件约700KB，可接受的大小

已创建 `scripts/build_standalone_html.py` 脚本，专门提取各指数chart HTML中的数据并构建自包含版本。

## LRN-20260331-003 | 缠论分析系统：指数轮动架构经验

**标签**: #chanlun #knowledge
**优先级**: medium
**状态**: validated
**分类**: knowledge_gap

### 详情

搭建指数轮动交易系统过程中的关键经验：

1. **数据源**：东方财富API在云服务器环境容易被封IP（RemoteDisconnected），新浪财经API更稳定，支持 `datalen=1023` 获取30分钟级别约6.5个月数据
2. **报告架构**：按日期分目录 (`YYYYMMDD/`)，保留latest快捷链接；用 `tracking.md` 持续追踪历史结论
3. **纯缠论评分**：5维度（走势分类30% + 信号强度25% + MACD动力学20% + 中枢结构15% + 级别共振10%）
4. **一买判断**：需要 a+A+b+B+c 结构中 c段MACD面积 < a段面积，多组hub对都检测可增加信号可靠性
5. **一买确认状态**：底分型确认 ≠ 完全确认，还需要完整上升笔形成并回到中枢附近

### 改进措施

见 `docs/指数轮动交易系统逻辑.md` 完整文档。

## LRN-20260331-004 | 缠论引擎：趋势背驰方向必须用中枢对方向判断

**标签**: #chanlun #correction #critical
**优先级**: critical
**状态**: validated
**分类**: correction

### 详情

`chanlun_engine.py` 的 `check_trend_divergence()` 函数中，趋势背驰信号的方向（一买/一卖）最初使用的是 c 段**最后一笔的方向**来判断。这导致：

- 在下跌趋势（中枢下移）中，当一买触发后价格反弹形成新的上升笔，c 段最后一笔变为上升方向 → 引擎错误地将信号从"一买"翻转为"一卖"
- 本质错误：**信号方向应由中枢移动趋势决定，不应由最后一笔的方向决定**

### 修复内容

修复 `check_trend_divergence()`：
1. 通过比较相邻中枢的 ZG/ZD 判断趋势方向（而非最后一笔方向）
2. 下降中枢对（curr.zd < prev.zd AND curr.zg < prev.zg）→ 只产生 一买
3. 上升中枢对（curr.zd > prev.zd AND curr.zg > prev.zg）→ 只产生 一卖
4. MACD面积对比只计算**同方向笔**的面积（下跌对比下降笔，上涨对比上升笔）
5. 触发笔取 c 段最后一笔同方向笔（而非最后一笔）

### 效果

- 上证50 30分钟一买 @ 2.88 正确保留（之前消失）
- 多个指数的信号评分显著改善
- 消除了下跌反弹中的虚假一卖信号

### 代码修改

```python
# Before (wrong): use last stroke direction
last_c = seg_c_strokes[-1]
divergences.append({'direction': last_c.direction, ...})

# After (correct): use hub-pair direction + filter same-direction strokes
is_downtrend = curr_hub.zd < prev_hub.zd and curr_hub.zg < prev_hub.zg
is_uptrend = curr_hub.zd > prev_hub.zd and curr_hub.zg > prev_hub.zg
trend_dir = -1 if is_downtrend else 1
c_dir_strokes = [s for s in seg_c_strokes if s.direction == trend_dir]
trigger_stroke = c_dir_strokes[-1]
divergences.append({'direction': trend_dir, 'date': trigger_stroke.end.date, ...})
```
