## 一、目标架构

每本 PDF 书籍最终产出四层文件，按查阅深度递增排列：

```
books/<书名>/
├── <原始>.pdf                    # L0 原始文件（归档保留）
├── <全文>.md                     # L4 全文提取（数千行，按行号查阅）
├── <总结>.md                     # L2 分组总结（数百行，一次可读完）
├── concept-index.md              # L3 概念索引（概念→课次→行号）
├── images/                       # 配图（文件名含页码）
├── extract.py                    # 提取脚本（可复用）
└── cleanup.py                    # 清洗脚本（可复用）

knowledge/
└── <操作框架>.md                  # L1 最精炼的可操作知识（数百行以内）
```

### 四层的作用

| 层级 | 文件 | 典型行数 | AI 使用场景 |
|------|------|---------|------------|
| **L1** | 操作框架 | 200-400 | 回答「怎么做」「规则是什么」 |
| **L2** | 分组总结 | 500-800 | 回答「哪一章讲了什么」「有什么图」 |
| **L3** | 概念索引 | 200-300 | 回答「X 的定义在哪」→ 给出行号 |
| **L4** | 全文 | 5000+ | 按 L3 行号读取原始表述 |

**核心原则**：AI 永远不需要一次性读 L4 全文。通过 L1→L2→L3 逐层缩小范围，最终只读 L4 的几十行。

## 二、第一步：PDF → 全文 Markdown

### 前置依赖

```bash
pip install pdfplumber Pillow
sudo apt install poppler-utils   # 提供 pdfimages 命令
```

### 提取流程

1. **创建目录结构**

```bash
mkdir -p books/<书名>/images
```

2. **提取图片**

```bash
cd books/<书名>/images
pdfimages -all ../../<原始>.pdf img
```

`pdfimages` 会生成 `img-000.ppm`、`img-001.jpg` 等文件。

3. **运行提取脚本**

以 `extract.py` 为模板（见 `books/缠论108课/extract.py`），核心逻辑：

```python
# 关键步骤
# a. 用 pdfimages -list 获取 图片序号→页码 的映射
# b. 将 PPM 格式转换为 PNG，按 p{页码}_{序号}.{ext} 重命名
# c. 用 pdfplumber 逐页提取文本
# d. 根据图片在页面中的垂直位置，将图片引用插入到对应文本行间
# e. 检测章节边界，插入 --- 分隔符
```

**关键参数**：
- 图片命名规则：`p{三位页码}_{页内序号}.png/jpg`，如 `p043_1.png`
- 章节边界检测正则：根据书籍结构调整（如 `r"^教你炒股票\s*\d+"` 或 `r"^第\d+章"`）

4. **输出文件**

```
books/<书名>/<全文>.md     # 带图片引用的全文
books/<书名>/images/      # 所有图片
```

### 提取要点

- **图片位置对齐**：`extract.py` 通过计算图片 `top` 坐标与文本行的比例关系来决定插入位置，不是完美的但足够用
- **PDF 表格**：`pdfplumber` 可提取表格为二维列表，按需处理
- **中文编码**：确保输出用 UTF-8
- **大 PDF 处理**：超过 200 页的 PDF 提取可能需要几分钟

## 三、第二步：文本清洗

以 `cleanup.py` 为模板（见 `books/缠论108课/cleanup.py`），核心任务：

1. **去除页码**：PDF 提取常带 standalone 数字作为页码页脚
2. **改善图片描述**：根据上下文关键词生成有意义的 alt text
3. **压缩空行**：最多保留两个连续空行
4. **修复格式**：如断行重组、特殊字符清理

### 清洗正则模板

```python
# 去页码：独立行的纯数字（前后有空行）
if stripped.isdigit() and 1 <= int(stripped) <= 500:
    if prev_empty or next_empty:
        continue

# 改善图片描述：查找附近的关键词上下文
keywords = ['分型', '中枢', '背驰', '走势', '买点', ...]
```

### 清洗后检查

- 用 `wc -l` 确认行数合理
- 抽查首尾几十行确认格式正确
- 确认图片引用路径有效

## 四、第三步：全文 → 总结文档

### 方法：并行子任务分段阅读

对于 5000+ 行的长文，一次性阅读不现实。策略：

1. **确定章节边界**

```bash
# 用 grep 找章节标题和行号
grep -n "^教你炒股票" <全文>.md
# 或
grep -n "^第\d+章" <全文>.md
grep -n "^---$" <全文>.md
```

2. **切分为 4-5 个段**

每段约 1500-2000 行，尽量在章节边界切分。

3. **并行子任务**

每个子任务给出：
- 要读取的文件和行范围
- 提取的维度（概念、规则、定理、图片引用）
- 输出格式模板

```
子任务 prompt 模板：

请阅读 <文件> 的第 X 行到第 Y 行（约覆盖第 N-M 章内容）。
对每章提取：
1. 核心概念
2. 操作规则
3. 定理/定律
4. 图片引用：images/pXXX_N.png - 说明什么

用中文输出。重点关注可操作的规则和技术概念，跳过纯评论内容。
```

4. **合并产出**

收集所有子任务的输出，按章节顺序组织为总结文档。

### 总结文档结构

```markdown
# <书名> 全文总结

## 目录
- [第一编 标题（第X-Y章）](#)
- ...

## 第一编 标题（第X-Y章）

### 第N章：标题
- 核心概念：...
- 操作规则：...
- 定理：...
- 📷 `pXXX_N.png` — 说明

## 附录 A：图片索引
## 附录 B：定理/公式汇总
## 附录 C：章节速览表（含重要度标注）
```

### 关键附录

- **图片索引表**：图片→章次→说明，方便 AI 知道何时查看图片
- **定理/公式汇总**：集中罗列，方便快速引用
- **速览表**：每章一行，标注重要度（★★★/●●/● 等），帮助 AI 判断优先级

## 五、第四步：总结 → 概念索引

### 方法：构建概念→行号映射

1. **提取全文中每章的精确起始行号**

```bash
grep -n "^第\d+章" <全文>.md
# 或对应格式的章节标题
```

2. **建立两张表**

**表一：章节行号对照**
```markdown
| 章次 | 全文起始行 | 标题 |
|------|-----------|------|
| 1    | 190       | ... |
```

**表二：概念速查**

按概念分类（如「基础概念」「操作方法」「辅助工具」等），每个概念给出：
- 首次定义的章次
- 全文中的起始行号
- 关键配图文件名

```markdown
| 概念 | 首次定义章 | 全文行号 | 关键图 |
|------|-----------|---------|--------|
| 分型 | 62        | 5185    | p162_1.jpg |
```

3. **附带 AI 查阅策略说明**

在文件末尾写明分层查阅策略，让 AI 知道应该按什么顺序查找。

## 六、第五步：提炼操作框架

从总结文档中提炼出**最精炼的可操作知识**，放入 `knowledge/` 目录。

### 原则

- **只放「每次都需要的」核心知识**，不放「偶尔查阅的」细节
- 行数控制在 200-400 行
- 按操作场景组织，而非按章节组织
- 包含决策流程图（如买卖点决策树）
- 包含速查表（如 MACD 速查、仓位配置表）

### 与总结的区别

| 维度 | L1 操作框架 | L2 总结 |
|------|-----------|--------|
| 组织方式 | 按操作场景 | 按章节 |
| 内容 | 规则、流程、表格 | 概念、定理、图片引用 |
| 粒度 | 粗（直接可用） | 细（含推导和上下文） |
| 更新频率 | 基本稳定 | 可扩充 |

## 七、第六步：集成到 Cursor 规则

在 `.cursor/rules/` 中的相关规则文件里，加入**知识库分层查阅表**：

```markdown
### 知识库（分层查阅）

| 层级 | 文件 | 行数 | 用途 |
|------|------|------|------|
| L1 快速 | knowledge/<框架>.md | ~400 | 操作规则 |
| L2 中等 | books/<书名>/<总结>.md | ~750 | 课程脉络 |
| L3 索引 | books/<书名>/concept-index.md | ~280 | 概念→行号 |
| L4 原文 | books/<书名>/<全文>.md | ~8600 | 按行号查 |
```

这样 AI 在触发相关规则时，自动知道按什么路径查找知识。

## 八、质量检查清单

### 提取后检查

- [ ] 全文 md 行数合理（一般 PDF 页数 × 30-50 行）
- [ ] 图片数量与 PDF 中的图片数一致
- [ ] 图片引用路径在 md 中可正确解析
- [ ] 无乱码和编码问题
- [ ] 章节边界正确（用 `---` 分隔）

### 总结后检查

- [ ] 每章至少有核心概念和操作规则的提取
- [ ] 重要图片在总结中被引用
- [ ] 附录包含定理汇总和速览表
- [ ] 速览表标注了重要度

### 索引后检查

- [ ] 行号与全文实际位置一致（抽查 3-5 个）
- [ ] 概念分类覆盖了主要主题
- [ ] 分层查阅策略说明清晰

### 集成后检查

- [ ] Cursor 规则中包含分层查阅表
- [ ] AI 可以按 L1→L2→L3→L4 路径找到任意概念

## 九、经验要点

### 提取阶段

1. **`pdfimages` 比 `pdfplumber.images` 更可靠**：`pdfplumber` 的图片提取在某些 PDF 上会丢失图片，`pdfimages`（poppler-utils）更全面
2. **图片命名包含页码**：`p{页码}_{序号}` 格式使得图片与原文位置可追溯
3. **PPM 转 PNG**：`pdfimages` 提取的 PPM 格式文件体积大，转 PNG 可大幅缩小
4. **章节检测正则需按书定制**：不同书的章节标题格式不同，提取前先翻几页确认

### 总结阶段

5. **并行子任务是关键**：8000+ 行的文件拆成 4-5 个并行任务，速度提升 3-4 倍
6. **切分在章节边界**：不要在章中间切，否则子任务可能误读上下文
7. **子任务 prompt 要具体**：给出「重点关注什么」的提示，避免子任务输出太多无关内容
8. **查看关键图片**：对概念定义类的核心图片（如分型笔线段示意图），AI 应直接读取图片文件理解内容，不能仅靠文字描述

### 组织阶段

9. **总结不超过 800 行**：超过则 AI 单次读取效率下降
10. **索引要包含行号**：这是让 AI 能精确定位 L4 原文的关键桥梁
11. **操作框架按场景不按章节**：用户问「怎么做」时，按场景索引比按章节索引更高效
12. **速览表的重要度标注**：帮助 AI 判断某章是否值得深入查阅

### 维护阶段

13. **新增 PDF 时复用模板**：`extract.py` 和 `cleanup.py` 的核心逻辑可复用，只需调整路径和章节正则
14. **全文 md 和图片生成后基本不变**：后续优化集中在 L1-L3 层
15. **Cursor 规则是入口**：确保每次新增知识库后更新规则中的分层表

## 附录：模板案例

```
缠论108课 完整产出：

books/缠论108课/
├── 缠中说禅：108课文字插图版.pdf     # L0 原始 PDF（10.7MB）
├── 缠中说禅108课.md                  # L4 全文（8603行）
├── 缠中说禅108课总结.md              # L2 总结（746行）
├── concept-index.md                  # L3 索引（280行）
├── images/                           # 154张配图
├── extract.py                        # 提取脚本
└── cleanup.py                        # 清洗脚本

knowledge/
└── 缠论108课操作框架.md                # L1 操作框架（391行）

.cursor/rules/
└── stock-chanlun-analysis.mdc        # Cursor 规则（含分层查阅表）
```

> 总 token 预算：L1（~400行 ≈ 2K tokens）+ L2（~750行 ≈ 4K tokens）+ L3（~280行 ≈ 1.5K tokens）= **~7.5K tokens**（远小于 L4 全文的 ~40K tokens）。AI 在 95% 场景下只需读 L1-L3 即可回答问题。
